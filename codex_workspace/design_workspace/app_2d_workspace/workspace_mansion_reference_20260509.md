# 2D 宅邸工作区设计参考 v0

> 目标：当用户不开启 AR 时，进入一个像素 2D 管理工作区。它不是 Web 控制台，而是 App 内的可操作空间。

## 核心概念

- 2D 工作区像一个宅邸主大厅。
- 不同区域对应不同任务：
  - 工作桌：批改、审批、报告、文件处理。
  - 日程区：Google 日程查看和确认。
  - 知识区：Obsidian / L1.5 设定 Node。
  - Nanobot 区：后台任务、报告、整理。
  - 通信区：LiveKit / 房间 / 对话。
- 场景里有角色可以对话，角色对应外部模块或助手能力。

## 交互参考

| 参考 | 借鉴方式 |
|:--|:--|
| 像素大厅 / 角色选择大厅 | 多区域入口、NPC、设备、工作桌、可走动空间 |
| Papers, Please 工作桌 | 文档拖拽、盖章、批准/驳回、丢弃、桌面分区 |
| 报纸开场 | 每日简报、任务开始、报告纸条 |

## 角色方向

| 角色 | 可能含义 |
|:--|:--|
| GOSLO Parrot | 主 companion，核心仍是鹦鹉 |
| Gemini / Gmail 副驾驶 | 外部服务或协助模块的人格化入口 |
| 女仆装橘色猫猫 | 家务/整理/工作区管理类角色 |
| Nanobot 原形象 | 后台 agent、报告、整理、执行任务的视觉锚点 |

## 工作桌动作

- 拖文件到桌面。
- 盖章批准 / 驳回。
- 丢到垃圾桶。
- 把纸条交给某个角色。
- 把结果贴回 Obsidian / Google / PhotoNode。

## 和 Web 控制台的区别

- 2D 工作区是 App 内可玩、可触摸、可角色化的管理空间。
- Web 控制台以后更偏状态监控、流程审计、后端可视化。
- 当前先设计 2D 工作区，因为它会反过来决定 Web 需要监控什么。
