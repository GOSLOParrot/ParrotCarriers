# 网页草图 vs Figma 工作流判断 2026-05-09

## 当前结论

当前阶段优先使用 `sketches/` 里的纯网页草图做布局和交互节奏；Figma 暂时作为正式视觉稿和组件沉淀工具，等像素素材、LOGO、字体和角色形象更明确后再精修。

## 为什么当前更适合网页草图

- Codex 内置浏览器可以直接预览本地草图，不受 Figma 登录态和 MCP 限额影响。
- 横屏 / 竖屏 / 抽屉展开这类布局，可以很快用 HTML/CSS 改。
- 可以做简单交互占位，例如展开、拉杆、切页、HUD 横向/纵向拉开。
- 文件放在 `codex_workspace/design_workspace/sketches/`，只作为设计草图，不进入 Unity / Web 生产代码目录。

## 如何避免“代码污染设计”

- 草图 HTML 不代表最终前端架构。
- 不在草图里决定正式路由、组件目录、状态管理、接口命名。
- 草图只服务于：
  - 布局比例
  - 操作区位置
  - 展开方向
  - 交互节奏
  - 素材占位尺寸
- 等 Figma 第一版和素材确定后，再反推 Unity UI 目录和 prefab TODO。

## Figma 什么时候更合适

- 像素字体、LOGO、角色 sprite、按钮素材都接近确定后。
- 需要整理可复用组件库时。
- 需要导出 PNG / 9-slice / UI reference 时。
- 需要把素材、颜色、字重和组件状态整理给 Unity 实现时。

## 推荐流程

1. 网页草图：快速确定布局和交互。
2. Figma：把稳定布局转成正式视觉和组件库。
3. Unity：按 Figma / 草图实现 MetaUI、Prefab、Canvas Scaler、输入交互。
