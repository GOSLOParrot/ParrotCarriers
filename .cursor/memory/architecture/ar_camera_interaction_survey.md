# AR 摄影与时光记录：需求调研问卷

> **阶段定位**: P2.5 核心互动玩法调研
> **目标**: 在设计底层数据流（如 `captureSnapshot`、DSG 挂载图片）之前，先确认我们要给用户呈现什么样的"摄影、打卡、事件留痕"的体感闭环。

---

## 🎮 一、优秀竞品参考与灵感机制

为了让 GOSLO 的 AR 体验不只是死板的"识物工具"，我们调研了市面上顶级的 AR/VR 和社交游戏互动机制。以下是一些可以直接借鉴的核心玩法概念：

### 1. 《Pokémon GO》 — GO Snapshot (AR 随拍)
- **机制**: 将宝可梦放在真实世界中，玩家可以绕着走寻找最佳角度。点击宝可梦会触发 "Strike a pose"（摆姿势）动画。
- **亮点**: 
  - **现实融合 (Reality Blending)**：宠物可以被真实世界物体遮挡。
  - **彩蛋机制 (Surprise Encounters)**：拍照时偶尔会有其他野生宝可梦乱入（Photobomb）。
- **启发**: 玩家说"摆个 pose"，GOSLO 立刻做一个特殊的动画（如歪头、比心），然后相机咔嚓记录。

### 2. 《VRChat》 — 丰富的相机系统 (Camera Mechanics)
- **机制**: 游戏内拥有高度自定义的相机设备。
- **亮点**:
  - **视觉分离 (Multi-layer/Stream)**：相机可以屏蔽 UI、隐身特定玩家，或者应用滤镜（景深、绿幕）。
  - **跟随模式 (Drone/Look-at-me)**：相机可以像无人机一样脱离玩家视角拍摄。
- **启发**: Unity 端可以进行**视觉分离**——给 Gemini / DSG 喂的是干净、无特效的原始客观画面（客观认知）；而截屏保存下来的照片带有 UI、贴纸、相框、GOSLO 滤镜（用户视角）。

### 3. 《光遇 (Sky: Children of the Light)》 — 摄影设备与共享记忆
- **机制**: 游戏内有专门的相机道具，提供自拍、三脚架等模式。
- **亮点**:
  - **共享记忆 (Shared Memories)**：玩家可以录制一段自己的影像（动作、声音），并将其留在地图上。其他路过的玩家可以看到这个"全息投影"重演当时的情景。
- **启发**: 拍摄的照片不仅是 `.jpg`，它可以作为一个 **"时光锚点" (Time-Based Metadata, TBM)** 存在。照片上绑定了位置、时间、天气。未来在 AR 世界中，用户走到旧地，可能会看到一张悬浮的照片记录着过去的瞬间。

### 4. 旅游打卡相机 App
- **机制**: 自动附加上下文元数据。
- **启发**: 拍下来的图片自带精美的 UI 边框，印有 `GOSLO AR` 的 Logo、当前的日期、甚至 Gemini 对当前环境的一句诗意短评（例如："2026-04-20 晴，和主人在咖啡馆发现了一只可爱的白色鼠标"）。

## 📝 二、架构概念预演 (不用现在设计代码)

虽然底层代码稍后设计，但我们需要对这套玩法的**流向**有个概念：

1. **触发阶段**: 玩家触发指令（如语音说"拍张照"，或者手指捏合）。
2. **体感阶段 (0-100ms)**: Unity 瞬间响应，GOSLO 摆 pose，播放"咔嚓"快门音效和白屏闪光（零延迟反馈）。
3. **分流阶段 (后台异步)**:
   - **用户层**: 生成一张带滤镜、加盖 UI 水印的美图，保存到手机相册或上传到 ECS 工作区图库。
   - **认知层 (DSG)**: 截取一张干净的图传给后端 Python，作为 `Reference Image` 挂载到 Graphiti 的时间轴或场景节点上。
4. **回放阶段**: 过了几天，用户问"昨天我们去咖啡馆你摆了什么 pose？"，Agent 通过图搜和时间轴标签，回想起照片并自然对话。
