# AR App Flow 与 UI 设计基线

> 定位：这是正式 AR App 的 **启动流程、UI 布局、功能入口与交互道具** 设计输入。  
> 边界：不继承 Sprint3 `Dev.unity` / Runtime HUD / SelfTest / 测试按钮；不把测试束当正式 App UI。  
> 追溯：原始灵感在 `lore/ideas.md`，研究整理在 `docs/sprint4_research/result/03_App_Flow_and_UI_Layout_Design.md`，旧问卷追溯在 `ar_app_plan.md`。

## 1. 当前判断

用户已经给出了足够清晰的初期 App Flow / UI 方向，可以作为 Sprint4 前置设计基线：

- 这是个人自用 Demo，优先“自己用得爽、所见即所得”，不优先大众化 onboarding。
- 核心是 AR 摄像头场景 + GOSLO 日常互动；复杂管理功能放到 Web 控制台或后续子项目。
- 2D UI 是 Meta UI / Overlay，不需要与真实世界做复杂遮挡、碰撞或物理交互。
- 视觉风格是 **2D 像素风 UI + 真实世界 AR 画面**。
- 默认主场景先做“大小姐宅邸”；海盗主题是 P3 以后换肤/主题扩展。
- UI 初稿已经足够进入功能入口与协议设计，不需要先追求完整像素资产和动画。

## 2. 用户原始设计摘录

> 首先这个demo本小姐不需要考虑用户，小姐我自己会用就行，这个是个给我自己用的demo，  
> AR启动，加载我们就正常的2D像素加载动画就行，加载好一个启动2D像素动画专场进入画面就直接进入AR场景就行，  
> HUD可开可关，2D显示一些状态和时间天气就可以了，依旧2D UI， 一个2D像素的 HUD组件，可点击横向展开或者竖向展开。 可以选择横向还是竖向可收纳的，  
> 另一个工具柜组件 在HUD组件 对角 也可以横向竖向展开，里面是一些组件 包括 设置、相机模式、进入2D像素的报告/行程/反馈消息处理工作区、  
> （工具区全2D 再独立设计 这部分就可以学 Paper Please 和 Last report了。AR场景/摄像头可以选择变暗成为被遮挡的背景，也可以先关闭。可能有不同的工作区和2D场景来处理不同的任务，这部分也是后续再设计）  
> 工具柜还有一个地方可以放 放大镜/海盗望远镜/ 简单行程和打勾 / 一个2D贴图箱可以拖出来到画面里截图打卡 / 一个2D像素风格的可以用手拖动的可以帮助鹦鹉提升注意力bounding box 小工具应该会很有意思 / 几个任务按钮 这些简单的小道具，可以展开到画面来用的，都可以设计的所见即所得。甚至可以有皮肤（就比如放大镜的主题皮肤就是海盗望远镜）等等。 其实 UI 就这两个 我们就先各自放对角，之后有什么更好的想法再改吧。。  
> 反馈消息可以有2D像素猫爪抓住纸条伸出，纸条可以点击展开阅读，或者拖进工作桌或者垃圾桶等等 注意2D UI 都是元界面（Meta UI）传统的 2D 界面就好了，不需要与真实世界互动。 UI就大致这样布局。

## 3. 本次补充的设计原话

> HUD 和 工具栏 的展开和对角安置设计的目的是，我不需要完成按照自己的手机位姿自动识别横屏竖屏（这个设计和自动转换又麻烦使用体验又极差）所以我们的展开由用户自己按方向展开，两个对角的HUD都好按用户的使用展开。

> 权限和连接那块可能有点不流畅，启动有点丑，但我也不确定在调试阶段要不要做成隐藏的。我觉得把它隐藏起来，放到加载动画里“正在 xxx、正在 xxx、正在 xxx”这样子，不如做成启动页的菜单选项吧：选择初始房间 / 选择 BrainAgent 管线 / 选择人设或场景（当然我们先完成大小姐宅邸的主场景）/ 选择房间 / 选择开启权限和连接测试等等。可以在启动页的菜单里，就像星露谷物语那样。具体的启动页设计后续再继续设计，这个初稿已经可以作为方向。

> Sprint4 要设计好的 UI 功能和流程：菜单先做好我们能选择的选项，菜单也能验证好功能。工具栏先设计原话说的那几个占位子，实际先完成放大镜和注意力框。放大镜记得可以调节放大倍率，注意是放大手机画面包括 UI。

> 注意力状态/工具还没决定归到 reflex / Intent / task。它应该是 Intent 和 task 级别的，或者两个任务并行启动：比如后台找，GOSLO 也停下来想想。用户希望 GOSLO 能理解意图，但不会突然阻断对话、插队或死盯着目标。这需要等行为模式、状态同步、ECP 的升级完成。这个工具也可以和物体按需发现的第一条路线一起验证协议升级完成状况。

## 4. 初期 App Flow

当前只固定高层流程，不锁死具体视觉稿：

1. 启动页 / 主菜单
2. 选择或确认初始配置
3. 权限与连接检查
4. 2D 像素加载动画
5. 2D 像素转场
6. 进入 AR 主场景
7. HUD / 工具柜按需展开
8. 工具或 2D 工作区按需进入

启动页不应只是隐藏调试按钮。它可以成为功能验证入口：让用户显式选择“本次会话是什么场景、用哪条管线、进哪个房间、开哪些权限、是否做连接测试”。

## 6. HUD 与工具柜布局

### HUD

- 位于屏幕一角。
- 显示基础状态、时间、天气、连接/感知摘要。
- 可开关、可收纳、可展开。
- 展开方向由用户选择，不自动依赖横屏/竖屏或手机姿态。

### 工具柜

- 位于 HUD 对角。
- 也是 2D 像素风 Meta UI。
- 可横向或竖向展开。
- 初期放置设置、相机模式、2D 工作区入口、放大镜、注意力框、纸条/报告入口、任务按钮等。

### 对角设计理由

对角布局的核心目的不是“好看”，而是减少自动适配复杂度：

- 不做复杂横竖屏自动切换。
- 不跟随手机位姿重排 UI。
- 让用户自己选择展开方向。
- 两个对角入口都能根据当前握持方式展开，降低遮挡中心 AR 视野的概率。

## 7. 工具柜初期道具

初期只定义位置和语义，不要求一次性全实现：

| 道具 | 用户语义 | 初期实现建议 |
|:--|:--|:--|
| 放大镜 / 海盗望远镜 | 放大手机画面，包括 UI | Sprint4 可先做；倍率可调 |
| 注意力框 / Bounding Box | 用户用 2D 框圈出关注区域，帮助 GOSLO 理解“看这里” | Sprint4 设计接口，可能与 `captureSnapshot` / `SightingEvent` 绑定 |
| 简易行程单 | 轻量任务/日程打勾 | 占位 |
| 2D 贴图箱 | 拖贴纸到画面用于截图打卡 | 占位 |
| 任务按钮 | 触发常用动作 | 占位 |
| 纸条 / 报告 | Nanobot / Maid 递交消息 | 占位，猫爪动画后续补 |

## 8. 注意力工具的开放问题

注意力框不是单纯 UI 控件，它会触发后端理解用户意图，所以暂不预设计实现，只记录问题：

- 它应归到 `Intent`、`Task`、`Reflex`，还是多层协作？
- 用户拖框时，GOSLO 应该立刻停下思考，还是后台先做识别？
- 这个动作是否应触发 `captureSnapshot`？
- 注意力框是否生成 `SightingEvent` 或 `SceneObservationEvent`？
- GOSLO 在识别期间如何避免打断对话？
- 如果用户只是“临时指一下”，命令多久过期？
- 它和 `identify_object Path1` 是否共用同一条按需视觉证据链？
- ECP 是否需要表达“正在关注某区域，但不强制中断当前说话”？

这些问题需要和行为模式、状态同步、ECP、DSG L2-B 一起设计。

## 9. Sprint4 UI / Flow 目标

Sprint4 不要求做完整前端美术，但需要把以下入口设计清楚：

- 启动页菜单能承载可选择项与调试项。
- HUD 和工具柜的布局、展开方向、收纳规则明确。
- 工具柜中至少有放大镜与注意力框的设计位置。
- 放大镜语义是放大手机画面，包括 UI。
- 注意力框语义能进入协议 V2 / ECP / DSG L2-B 设计讨论。
- 2D 工作区、纸条、猫爪、报告处理作为后续 UI 扩展保留。

## 11. Memory 目录整理判断

当前 `.cursor/memory/architecture` 确实混入了三类文件：

- 架构设计：如 `module_map_p2.md`、`bus_v4.md`、协议/DSG/AR 设计。
- 计划与前置：如 `ar_feature_implementation_plan.md`、`sprint4_pre_entry_prompt_and_plan.md`。
- 完成报告与历史追溯：如 sprint completion report、旧问卷、审计报告。

客观上这对 AI 仍然可读，因为 `INDEX.md`、frontmatter 的 `status/category`、`active_context.md` 能提供路由；但对人眼已经不够清晰。

暂不建议现在大规模移动目录，原因：

- 旧文件互相引用较多，移动会产生大量路径修补。
- Sprint 完成报告虽然不是架构，但仍是架构决策追溯的一部分。
- 当前最重要的是 Sprint4 前置设计，不是重构 memory 目录。

建议采用渐进方案：

1. 先用 `INDEX.md` 明确“当前必读”和“历史追溯”。
2. 新文件一律写清楚 `status` / `category` / `定位` / `边界`。
3. 后续如果要整理，再新建 `plans/` 或 `reports/`，并只移动已稳定归档的文件。
4. 移动前先做引用清单，避免破坏新 Chat 启动提示词。
