# nanobot 近期问题摘要

## 近期公开问题

### `#2775` 无法调用工具，只输出文字

提示：

- 借鉴 `nanobot` 模式时，要注意模型与工具调用能力是否匹配
- 不能默认认为所有模型都能稳定处理结构化工具调用

### `#2772` 微信返回消息数受限

提示：

- 渠道层会引入平台约束
- 对 `ParrotCarriers` 来说，这再次说明聊天渠道能力不应主导当前 Bus 设计

### `#2696` DingTalk 发送 html 文件报错

提示：

- 渠道适配细节繁杂，不适合当前项目过早继承

### `#1922` nanobot-webui

提示：

- 生态会继续长出管理面板 / 前端界面
- 但当前项目不应把这类外围工具当成主线阻塞项

## 当前项目的结论

1. `nanobot` 值得借鉴的是运行时模式
2. 当前不应把聊天渠道兼容层作为引入重点
3. 若后续借鉴其工具调用与后台任务能力，应优先验证模型兼容性与失败回收路径
