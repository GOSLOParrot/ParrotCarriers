# 内容放置判断

用于判断每个内容点应该放在演讲稿、PPT，还是仅作为答辩备用材料。

| 内容点 | 适合演讲稿 | 适合 PPT | 备用 / 不讲 | 判断理由 |
| --- | --- | --- | --- | --- |
| 相机拍照流程 | 是 | 是 | 否 | 演讲稿讲“为什么要双通道和Ref绑定”，PPT画数据流 |
| 语音跳舞 / RPC / ECP ACK | 是 | 是 | 否 | 演讲稿讲前台Intent闭环，PPT画命令和ACK闭环 |
| GOSLO派发改日程任务给nanobot | 是 | 是 | 否 | 最能体现Task：前台确认后，后台Worker处理Google Calendar变更 |
| 触发器协议 | 是 | 是 | 否 | 演讲稿讲“触发器能做什么”，PPT画TriggerKind和TriggerOutcome |
| Graphiti自然语言搜索 / 预加载 | 是 | 是 | 部分备用 | 作为触发器协议和长期记忆回灌的例子，不单独抢主线 |
| 相机模式Photo Awareness | 是 | 是 | 部分备用 | 作为事件触发/安全时机提醒的例子，注意它在代码中是Photo Awareness策略桥，不是普通RPC动作 |
| 代码函数名和文件名 | 否 | 否 | 是 | 答辩主线不讲代码细节，必要时作为问答依据 |
| Blackboard内部键名 | 少量 | 少量 | 部分备用 | 正文只讲共享状态面，PPT可显示“ACK状态面”，不展开键名 |
| `nanobot`是否为LiveKit挂载模块 | 是 | 否 | 否 | 需要在演讲稿中明确纠偏：本项目主路径是后台Worker/Redis任务链 |
