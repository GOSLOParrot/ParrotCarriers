# 03. App 启动流程与 UI 布局设计 (User Design Decision)

> **背景说明**：由于 DeepResearch 针对 UI/UX 的调研结果偏离预期（过滤过度、决策杂乱），本文件直接记录由用户（开发者本人）主导的 UI 布局与前端交互设计决策。当前阶段目标为“个人自用 Demo”，优先保证开发可行性、个人审美偏好与核心功能的闭环。

观前提示：我们先完成简单能看的设计就好了，后续我自己把2D像素资源 和动画补上，你要先用什么代替按你的方便来就可以。。

## 1. 核心设计理念
- **Meta UI (元界面)**：所有的 2D UI 组件都是传统的 2D 屏幕覆盖层（Overlay），不需要与真实物理世界（AR 空间）发生复杂的深度遮挡或物理交互。这样切分干净，开发简单方便。
- **视觉风格**：**2D 像素风 (Pixel Art) + 真实世界 AR 画面 (User 视角)** 融合。
- **目标受众**：开发者自用 Demo，无需过度迎合大众用户的通用 Onboarding 习惯，以“自己用得爽、所见即所得”为最高准则。

## 2. 启动流程 (Onboarding & App Flow)
- **加载阶段**：使用常规的 2D 像素风格加载动画。
- **场景过渡**：加载完成后，播放一个 2D 像素动画转场（Transition），结束后直接进入核心的 AR 摄像头场景。

## 3. 核心 UI 布局 (HUD 与 工具柜)
整体布局采用**对角线分布**，保持画面中心（AR 视野）的干净，避免遮挡主要互动对象（GOSLO）。

### 3.1 HUD 组件 (状态显示)
- **位置**：占据屏幕的一个角落（与工具柜对角）。
- **视觉与交互**：2D 像素风格，可点击进行横向或竖向展开/收纳。支持全局开启或关闭。
- **功能**：显示基础状态、时间、天气等信息。

### 3.2 工具柜组件 (Tool Cabinet)
- **位置**：在 HUD 的对角位置。
- **视觉与交互**：同样支持横向或竖向展开/收纳。
- **内置功能入口**：
  - 设置 (Settings)
  - 相机模式 (Camera Mode)
  - **工作区入口**：进入 2D 像素的报告/行程/反馈消息处理工作区。

## 4. 2D 工作区与互动小道具 (Interactive Props)

### 4.1 沉浸式 2D 工作区 (Workspace)
- **参考竞品**：深度借鉴《Papers, Please》和《Last Report》等独立游戏的复古 UI 与文档处理体验。
- **视觉表现**：进入工作区时，底层的 AR 场景/摄像头画面可以变暗作为背景，或者直接关闭以节省性能。
- **扩展性**：未来可能针对不同的任务（如批改行程、查阅图谱）设计不同的 2D 场景和工作桌。

### 4.2 拖拽式互动小道具
工具柜中存放了多种“所见即所得”的 2D 像素小道具，可以直接拖拽到 AR 画面中使用：
- **放大镜 / 海盗望远镜**：支持皮肤系统（如默认是放大镜，海盗主题下变成望远镜）。
- **简易行程单**：支持打勾操作。
- **2D 贴图箱**：可以从中拖出贴图到 AR 画面里，用于拍照打卡。
- **注意力引导框 (Bounding Box)**：一个可以用手拖动的 2D 像素框，套在画面中的物体上，用来物理（视觉）辅助提升鹦鹉 (GOSLO) 的注意力。
- **任务按钮**：其他简单的快捷操作触发器。

### 4.3 消息反馈机制 (Notification)
- **表现形式**：当后台 AI (Nanobot/水手) 递交报告时，屏幕边缘会伸出一个 **2D 像素猫爪** 抓住一张纸条。
- **交互逻辑**：纸条可以点击展开阅读，也可以直接拖拽进 2D 工作桌进行处理，或者拖进垃圾桶销毁。

## 5. 历史灵感与主题设定追溯
*(摘录自之前的交流与 @ideas.md)*
- **主题换肤 (Theme & Skins)**：基础设定为“大小姐宅邸”（GOSLO 是大小姐，Nanobot 是女仆）。未来可平滑切换至“海盗主题”（User 是船长，GOSLO 是戴眼罩的大副，Nanobot 是水手，UI 变成羊皮纸和望远镜，摄像头画面可加脏镜片滤镜）。

如果你希望能挖出高质量的“2D 像素复古 UI + 批改报告/管理”的设计方法论与设计共识，我建议在提示词中替换或补充以下几款知名度更高、且设计界有大量拆解文章的经典游戏：

《Papers, Please》（请出示文件）
为什么合适：这是“复古像素 UI + 沉浸式批改文件”的绝对标杆。关于它如何在一个狭小的 2D 屏幕上安排海量文本、印章、纸条递交动画，设计界有无数的拆解文章。
《Do Not Feed the Monkeys》（不要喂食猴子）
为什么合适：像素风格，核心玩法是“监控多个屏幕 + 记录/提交报告”。它很好地处理了“复古像素画面”与“现代信息管理（聊天、邮件、记事本）”的 UI 融合。
《Return of the Obra Dinn》（奥伯拉丁的回归）
为什么合适：虽然是 1-bit 3D 风格，但它的核心交互是“在一个 3D 空间里翻开一本 2D 的复古调查报告进行填写”。关于它如何无缝切换 3D 探索和 2D 报告填写的 UX 设计，有很多 GDC 演讲和深度分析。
《Death and Taxes》（死神与税赋）
为什么合适：虽然不是纯像素风，但核心玩法完全是“在办公桌上批改 2D 纸质报告”，对于“纸条递交”、“桌面 UI 布局”有很好的参考价值。

虽然我们的2D UI 与 3D世界 没什么碰撞上的交互/互动，所以学不要学岔了。。
